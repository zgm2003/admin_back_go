# AI 模型官方数值定价与钱包结算设计

**日期：** 2026-07-24  
**状态：** 待书面复核

## 1. 目标

项目已经完成充值与钱包入账闭环，但 AI 调用尚未产生钱包消费。本设计补齐对话、文本、图片、视频、音频和智能体生成的用量计费，并保持现有模块边界、幂等语义和资金安全。

核心公式只有一条：

```text
最终费用
  = Σ（模型官方数值人民币基准价 × 实际分类用量）
  × 智能体消费倍率
```

例如，厂商官方价格为 `$5 / 1M input tokens`，平台基础价直接采用 `¥5 / 1M input tokens`。只保留官方价格的数值并将平台结算币种定义为人民币，不进行美元兑人民币换算，也不增加汇率配置。

## 2. 已确认的业务规则

1. 模型基础价格来自厂商官方公开价格。
2. 官方价格数值直接作为人民币价格：`$5 / M Token -> ¥5 / M Token`。
3. 该规则命名为 `official_numeric_parity_v1`，不能描述成“官方人民币汇率换算价”。
4. 管理员不能新增、编辑或覆盖模型基础价格。
5. 管理员只在智能体上配置一个消费倍率。
6. 智能体倍率默认 `1.0`，必须大于零。
7. 供应商和供应商模型不保存消费倍率。
8. 模型之间的成本差异由官方基础价表达；智能体之间的产品售价差异由智能体倍率表达。
9. 智能体更换模型后自动采用新模型的官方基础价，智能体倍率保持不变。
10. 价格目录或倍率更新只影响后续消费，历史账单永不重算。
11. 普通输入、输出、缓存写入和缓存读取必须分别记录、分别计价。
12. 缓存命中的 Token 不能再次按普通输入 Token 计费。
13. 官方区分 5 分钟、1 小时等缓存写入价格时，必须分别记录对应 TTL 档位。
14. 图片、视频和音频遵循各模型的官方计费单位，可以是 Token、张、秒、分钟、字符或次。
15. 价格缺失、规格不匹配或用量口径不完整时，禁止按零元静默放行，也禁止猜一个更高价格扣用户的钱。
16. 钱包可用余额不能因为 AI 结算变成负数。

## 3. 当前项目事实与架构约束

现有后端继续遵守：

```text
route -> handler -> service -> repository -> model
```

与本需求直接相关的事实如下：

- `ai_agents` 已选择一个供应商和模型，并保存支持的场景。
- `ai_provider_models` 只有供应商模型 ID、展示名和状态，没有定价身份或商业倍率。
- `ai_runs` 已保存用户、智能体、供应商、模型、请求幂等身份、状态和输入/输出/总 Token。
- 一次对话运行可能因为工具调用产生多次模型请求。
- `ai_provider_attempts` 已为队列对话提供持久化的供应商尝试身份。
- 图片与文本可能由 Worker 执行；视频是供应商异步任务；音频当前只返回响应体，没有统一用量元数据。
- `user_wallets` 与 `wallet_transactions` 当前以人民币“分”的整数保存金额。
- 钱包扣款/入账已具备行锁、余额不足拒绝和 `(source_type, source_id)` 幂等约束。
- `SourceAIGenerate` 与 `SourceAIRefund` 已存在，但 AI 运行时尚未调用钱包。
- 旧 `ai_billing_rules`、`ai_billing_records` 已被有意删除，必须继续保持不存在。
- 应用启动过程不能执行数据库迁移。
- 可以新增权限定义，但不能自动授权，也不能直接写 `role_permissions`。

模块所有权固定为：

- `pricing` 负责价格目录、模型解析、报价和确定性计算。
- AI 驱动层负责解析并归一化各供应商的原始用量。
- `usagecharge` 负责用量账单、计费明细、状态机和结算编排。
- `wallet` 负责余额、冻结、补充冻结、扣款、释放、退款和钱包流水。
- AI 业务服务只依赖小接口，不复制价格公式，也不直接修改钱包表。
- handler 只处理传输协议，不直接查询计费或钱包数据。

## 5. 方案选择

### 5.1 全局倍率：不采用

实现简单，但无法让两个智能体采用不同商业策略，一次调价会影响整个平台。

### 5.2 供应商模型倍率：不采用

能够区分模型，却把产品价格策略绑定到了基础设施。同一模型被两个智能体使用时无法分别定价。

### 5.3 中央价格目录 + 智能体倍率：采用

官方价格事实只保存一份，智能体保存面向用户的消费策略。同一模型可供多个智能体复用并采用不同倍率；智能体切换模型时只替换基础价。

价格目录采用仓库内审核并随版本发布的文件，不直接依赖运行时社区价格源。`sub2api` 的解析、回退和多计费单位设计可作参考，但它使用的 LiteLLM 兼容目录并不是厂商官方 API，不能未经审核成为本项目的资金事实源。

## 6. 总体架构

```text
厂商官方价格页面
  -> 仓库内审核的版本化价格目录
      -> 模型价格解析器
          -> 规范模型 + 当前有效价格项

智能体运行快照
  -> 智能体消费倍率

供应商响应
  -> 供应商驱动归一化
      -> 分类用量明细

价格项 + 分类用量 + 智能体倍率
  -> 确定性金额计算器
      -> AI 用量账单/明细
          -> 钱包冻结/扣款/释放
              -> 钱包流水
```

后端新增两个职责单一的 AI 能力：

1. `pricing`：加载并校验内嵌目录，解析规范模型，生成冻结上限报价，计算精确费用。
2. `usagecharge`：管理账单状态、分类明细、指纹和钱包资金接口的调用顺序。

Chat、text、image、video、audio 和 agent-generation 服务通过接口接入，运行时统一装配具体实现。

## 7. 官方数值价格目录

### 7.1 事实源

价格目录固定为：

```text
contracts/ai-pricing/v1/catalog.json
contracts/ai-pricing/v1/catalog.schema.json
```

目录在构建时嵌入后端。每个版本必须包含：

- 单调递增的目录版本；
- 规范内容的 SHA-256；
- 发布时间和人工核验时间；
- `official_numeric_parity_v1` 计价策略；
- 官方来源 URL；
- 模型厂商、规范模型 key 和显式别名；
- 支持的模态、计量能力、用量归一化 profile 和冻结估算 profile；
- 带生效时间的结构化价格项。

运行时不能修改目录。后台只读展示当前目录。官方价格变化必须通过新的目录版本和应用发布生效。

每笔账单快照目录版本、摘要、官方原始币种/数值、人民币基准数值和来源，因此后续目录更新不能改变历史费用。

### 7.2 模型身份解析

`engine_type` 表示 API 协议，不代表价格厂商。解析器使用供应商模型 ID 和目录内的显式别名选择规范模型：

1. 精确匹配规范模型 key；
2. 精确匹配目录声明的别名；
3. 否则返回 `pricing_model_unavailable`。

禁止模糊前缀、日期后缀猜测或回退到名字相近的模型。别名出现歧义时，整个目录校验失败。

供应商模型接口可以只读返回规范价格模型和定价就绪状态，但不增加可编辑单价。未知别名必须通过审核后的目录更新解决。

### 7.3 价格项

价格项使用受控字段，不使用任意 JSON 配置：

- `metric_code`：如 `input_text_token`、`output_text_token`、`cache_read_token`、`cache_write_5m_token`、`cache_write_1h_token`、`generated_image`、`video_millisecond`、`audio_millisecond`、`input_character`；
- `tier_key`：明确的图片尺寸/质量或视频分辨率档位；
- `quantity_unit` 与 `price_quantity`：如每百万 Token、每张、每 60000 毫秒、每百万字符；
- 官方币种与官方十进制数值；
- 数值相同的人民币结算价；
- 生效时间与官方来源。

默认只使用官方标准按量价。priority、flex、batch 等档位只有在目录明确存在且请求明确选择时才可使用，不能根据供应商账户自行猜测。

## 8. 智能体消费倍率

`ai_agents` 新增整数定点字段 `billing_multiplier_ppm`：

```text
1_000_000 = 1.0 倍
1_500_000 = 1.5 倍
```

接口使用十进制字符串，避免 JavaScript/JSON 浮点改变金额。允许范围固定为 `0.000001` 至 `1000.000000`，对应 `1` 至 `1_000_000_000` ppm。零、负数、超精度和超范围值全部拒绝。

启用智能体前，所选模型必须覆盖该智能体所有启用场景所需的价格和计量能力。智能体页面只读展示解析后的价格。

倍率和模型在账单第一次调用供应商前完成快照。同一运行重试继续使用原快照；管理员修改只影响之后的新运行。

## 9. 分类用量与缓存公平性

### 9.1 统一用量契约

现有 `PromptTokens`、`CompletionTokens`、`TotalTokens` 只适合运行统计，不足以支持资金结算。驱动层必须返回结构化归一用量，包括：

- 用量状态及字段是否真实存在；
- 供应商请求身份；
- 一个或多个受控用量项；
- 当前驱动采用的原始字段语义；
- 完整性与守恒校验结果。

每个用量项保存调用序号、`metric_code`、`tier_key`、整数数量和数量单位。`ai_runs` 的总 Token 继续作为监控汇总，账单明细才是资金事实。

### 9.2 缓存必须拆分

输入用量归一化后分为互斥类别：

```text
普通输入
缓存写入（必要时按 TTL 再拆分）
缓存读取
```

输出单独记录。驱动必须校验数量非负，并按供应商字段语义验证输入总量守恒。

典型规则：

- OpenAI 的 `prompt_tokens_details.cached_tokens` 是 prompt tokens 的子集，因此普通输入为 `prompt_tokens - cached_tokens`，缓存部分记录为 `cache_read_token`。
- 如果供应商分别返回普通输入、缓存创建和缓存读取，则直接映射为三个互斥用量项。
- 5 分钟和 1 小时缓存创建不能先合并再计价。
- 工具对话的每次模型调用分别记录缓存读写，最终整次运行只汇总一次。

### 9.3 缺失缓存明细时禁止猜价

驱动必须区分“字段不存在”和“字段存在且为 0”。当模型存在独立缓存价格，但供应商响应无法区分普通输入与缓存输入时，该用量标记为不完整。

不完整或不合法的用量不能全部按普通输入高价扣款。账单进入 `unbilled`，释放用户冻结金额，并记录可诊断的计费故障。如果流式内容已经到达用户，平台承担这次异常成本，也不能拿估算值向用户扣款。

如果模型官方规则本身没有缓存价格，则完整的输入总量可以直接按普通输入计费。

## 10. 人民币精确金额

### 10.1 内部单位

钱包和账单统一使用整数单位：

```text
1 元 = 100_000_000 money units
1 分 = 1_000_000 money units
```

目录价格和倍率均从字符串解析。金额计算使用带溢出检查的整数/有理数运算，价格、余额、冻结和账单禁止使用 `float32` 或 `float64`。

对全部计费项 `i`：

```text
精确基础费用 = Σ(quantity_i * unit_price_units_i / price_quantity_i)
精确最终费用 = 精确基础费用 * multiplier_ppm / 1_000_000
实际扣款单位 = floor(精确最终费用)
```

整笔账单只向下取整一次，偏差归用户。各明细使用确定性的最大余数分配，保证明细之和严格等于总扣款。

### 10.2 缓存示例

假设：

- 普通输入 `¥5 / M Token`；
- 缓存读取 `¥0.5 / M Token`；
- 输出 `¥15 / M Token`；
- 智能体倍率 `1.5`；
- 实际用量为普通输入 900、缓存读取 100、输出 50 Token。

```text
基础费用 = (900 * 5 + 100 * 0.5 + 50 * 15) / 1_000_000
         = ¥0.0053

最终费用 = 0.0053 * 1.5
         = ¥0.00795
```

100 个缓存 Token 只按缓存价计算，不会再次进入普通输入。

## 11. 钱包精度与资金冻结

### 11.1 唯一余额事实

现有钱包“分”字段迁移为 money units 字段，不保留两套可写余额事实。

`user_wallets` 保存：

- `balance_units`：总余额；
- `held_units`：冻结金额；
- `total_recharge_units`：累计充值；
- `total_consume_units`：累计消费。

可用余额恒等于 `balance_units - held_units`。充值订单和套餐仍可使用“分”，充值成功时精确乘以 `1_000_000` 后入钱包。

`wallet_transactions` 的金额及变动前后余额改为 money units。接口返回十进制人民币字符串，不能把 int64 直接作为 JSON number。充值显示两位小数；AI 消费与余额最多显示 8 位并去除无意义尾零。

### 11.2 冻结状态机

钱包新增资金冻结记录，支持：

```text
reserve  -> 增加 held_units
top up   -> 将当前冻结补充到新的总额
capture  -> 减少 held_units 与 balance_units，并写一条扣款流水
release  -> 只减少 held_units
```

每个冻结使用唯一 `(source_type, source_id)`，AI 的 `source_id` 为用量账单 ID。最终扣款使用 `SourceAIGenerate`；结算后需要冲正时使用 `SourceAIRefund`。释放未扣款的冻结不是退款，不产生收入流水。

冻结、补充、扣款和释放都锁定钱包行并保持幂等。最终扣款与账单终态通过事务化 wallet port 在同一数据库事务提交，`usagecharge` 不能复制钱包余额规则。

## 12. 持久化模型

### 12.1 `ai_usage_charges`

每个可计费 `ai_run` 最多一张用量账单，快照：

- run、request、user、agent、provider、model 身份；
- 规范价格模型；
- 目录版本、摘要和数值人民币策略；
- 智能体倍率；
- 模态、请求指纹；
- 报价上限、最终扣款和金额精度；
- 状态、诊断码和关键时间。

`run_id` 唯一、可空，并使用 `ON DELETE SET NULL`。会话或运行数据删除时不能级联删除财务事实，账单自身的身份快照必须足够审计。

状态固定为：

```text
pending -> reserved -> settled
                   -> released
                   -> uncertain -> settled | released | unbilled
pending -> rejected
reserved -> unbilled
```

`settled`、`released`、`rejected`、`unbilled` 都是终态。退款通过新的钱包入账记录表达，不能修改已结算账单金额。

### 12.2 `ai_usage_charge_items`

计费明细为追加写事实，保存：

- 账单 ID、供应商调用序号；
- 可选的 provider-attempt 与 provider-request 身份；
- `metric_code`、`tier_key`、数量、数量单位；
- 定价数量单位和人民币单价；
- 官方原始币种/数值、人民币数值；
- 分配后的基础金额与最终金额；
- 用量指纹和价格指纹。

唯一的调用/指标/档位身份阻止 Worker 重试重复写入。即使账单最终释放或不扣费，明细仍保留，便于区分供应商实际成本与用户实际扣款。

### 12.3 `wallet_holds`

钱包冻结保存 wallet、user、source、冻结金额、已扣金额、状态、请求指纹、过期时间及终态时间。只允许 `active`、`captured`、`released`，不使用软删除。

## 13. 请求与结算流程

### 13.1 调用供应商之前

1. 创建或恢复规范 `ai_run`，取得稳定 ID。
2. 加载智能体、供应商和模型快照。
3. 解析规范模型与所需价格项。
4. 创建账单并快照目录与智能体倍率。
5. 计算保守的最大费用报价。
6. 在钱包冻结该金额。
7. 价格、计量能力或余额校验失败时，不调用供应商。

供应商缓存是否命中只有响应后才能确定。为防止透支，Token 请求的临时冻结按普通输入、缓存写入和缓存读取中的最高适用价格估算；最终只按真实缓存分类扣款并立即释放差额。冻结不是扣款。

每个 Token 请求必须有明确的最大输出 Token。请求未提供时，运行时使用产品上限与目录模型上限中的较小值。

目录为模型绑定受控的冻结估算 profile。估算器接收最终序列化的供应商请求并返回保守输入 Token 上界，禁止用通用字符数随意猜测。没有经过测试的估算 profile 或输出上限时，该模型不能进入计费就绪状态。

工具对话每次追加模型调用前都补充同一冻结。余额不足时必须在下一次供应商调用前停止。

### 13.2 供应商响应之后

1. 驱动校验并归一化用量。
2. 按调用序号幂等追加计费明细。
3. 如果还有模型调用，先补充冻结再继续。
4. 运行成功时只计算一次精确总费用。
5. 同一事务内扣除精确金额、释放多余冻结、写钱包流水并将账单设为 `settled`。
6. 非流式的持久化结果只能在结算事实落库后标记成功。

如果实际费用意外超过保守冻结，禁止透支钱包。账单记录估算器不变量错误并进入恢复流程，不把“调用后再负数扣款”当成正常路径。

### 13.3 失败与不确定结果

- 调用供应商前失败：立即释放冻结。
- 未形成可计费成功结果的失败、取消或超时：释放冻结，不扣用户。
- 结算数据库暂时失败：保留冻结，使用相同指纹重试结算，不能重复调用供应商。
- 调用已发出但结果未知：账单进入 `uncertain`，冻结保留到供应商/任务对账或该模态恢复期限。
- 到期仍无法得到准确用量：释放冻结并设为 `unbilled`，不能把估算金额当成实际消费扣除。

## 14. 各模态规则

### 14.1 对话、文本与智能体生成

- 每次真实模型调用都计量，包括工具调用后的模型轮次。
- 本地工具执行与本地知识检索本身不收费；它们独立调用计费模型时才产生新用量。
- 普通输入、缓存写入、缓存读取、输出以及官方明确区分的图像/音频 Token 分别记录。
- `ai_runs` 保存统计汇总，账单明细保存计费分类。

### 14.2 图片

- 按张模型根据请求数量、尺寸和质量冻结，并按实际成功的可计费输出数量结算。
- Token 计价的图片模型必须记录图片输入/输出 Token，不能伪装成按张价格。
- 部分成功按实际成功数量和真实用量结算。
- Worker 重试复用同一 run 与账单身份。

### 14.3 视频

- 创建供应商任务前，根据时长、分辨率、音频选项和官方计费项冻结。
- 供应商任务处理中继续保持冻结。
- 持久化成功后扣款；失败、取消或超时释放。
- 过期任务使用统一账单恢复流程，不增加媒体专用的第二套余额逻辑。

### 14.4 音频

- 音频驱动结果必须补充结构化计量元数据。
- 按字符计费时使用规范化请求字符数。
- 按时长计费时使用供应商时长或确定性的媒体时长解析结果。
- 按 Token 计费时使用分类输入/输出 Token。
- 缺少官方计费项要求的数据时设为 `unbilled`，不能拿响应字节数猜时长或 Token。

## 15. 幂等、事务与恢复

稳定幂等链为：

```text
ai_run.id
  -> ai_usage_charges.run_id（唯一）
      -> wallet_holds(ai_usage, charge_id)（唯一）
      -> wallet_transactions(ai_generate, charge_id)（唯一）
      -> wallet_transactions(ai_refund, charge_id)（需要时唯一）
```

计费明细额外使用调用序号和用量指纹。同一身份、同一指纹的重试返回既有结果；同一身份出现不同用量或价格指纹时必须报冲突，不能覆盖。

Worker 只扫描已过恢复期限的非终态账单/冻结，使用租约和有界批次执行幂等恢复。恢复只能根据持久化真实用量结算，或根据已证明失败释放。

禁止“账单先成功、钱包之后 best-effort 扣款”，也禁止钱包已扣而账单仍对外报告未结算。

## 16. Admin API 与界面

### 16.1 智能体配置

智能体新增/编辑接口增加：

- 十进制字符串消费倍率；
- 只读规范价格模型；
- 只读定价就绪状态；
- 当前模型/场景所需的只读基础价格项。

选择供应商模型后刷新价格预览。缺少价格或计量能力时，表单不能启用该智能体。

### 16.2 只读价格目录

新增 `/ai/pricing` 只读页面，展示模型、模态、单位/档位、官方来源数值、人民币基准值、来源 URL、目录版本和核验时间。

页面与读取接口使用 `ai_pricing_list` 权限。不存在价格新增、编辑、删除接口。

智能体表单所需价格预览随已有 agent page-init/detail 返回；拥有 `ai_agent_add` 或 `ai_agent_edit` 的管理员不必额外拥有独立价格目录权限才能编辑智能体。

### 16.3 运行与钱包详情

运行详情增加：

- 账单状态与总费用；
- 目录、模型与倍率快照；
- 普通输入、各缓存写入档位、缓存读取、输出和媒体用量；
- 单价、分项金额与异常恢复状态。

钱包摘要区分总余额与可用余额。AI 流水最多显示 8 位小数并链接到账单/运行详情。缓存 Token 及其折扣价必须可见，便于核对没有按普通输入多扣。

新增 `ai_pricing_list` 权限定义并进入 route metadata 与 Admin Contract Bundle，但不自动赋予任何角色，也不写 `role_permissions`。

## 17. 错误与可观测性

稳定错误类别至少包括：

- 价格模型不存在或别名冲突；
- 所需价格档位不存在；
- 智能体倍率非法；
- 驱动不具备所需计量能力；
- 供应商用量缺失或不合法；
- 缓存分类不完整；
- 可用余额不足；
- 冻结冲突或过期；
- 结算指纹冲突；
- 供应商结果不确定；
- 恢复失败。

日志记录 run、charge、hold、provider、model、目录版本和 provider request ID，不记录 API key、prompt 或生成内容。

指标至少覆盖账单状态、冻结金额、结算延迟、未计费用量、缓存读取 Token、缓存节省金额、价格解析失败和过期冻结恢复。

## 18. 数据迁移与发布顺序

数据库迁移由版本化脚本执行，不能放进应用启动：

1. 增加智能体倍率、账单/明细、钱包冻结、约束和索引。
2. 每个旧钱包金额从“分”精确乘以 `1_000_000`，逐钱包和汇总校验后再删除旧 cents 字段。
3. 钱包流水金额和前后余额按同一规则转换并校验守恒。
4. 校验并内嵌价格目录。
5. 现有智能体倍率回填为 `1.0`，未知模型不能猜测目录映射。
6. 未定价或不可计量模型标记为 billing-unready，调用供应商前失败。
7. AI 运行接入与 Worker 恢复和钱包冻结状态机一起发布。
8. 从编译后的路由重新生成 Admin Contract Bundle 与前端客户端。

迁移验收必须证明：

- 每个钱包和流水的旧 cents 与新 units 精确相等；
- 迁移钱包 `held_units = 0`；
- 余额、冻结、累计金额和流水金额非负；
- `balance_units - held_units >= 0`；
- 流水变动前后金额仍守恒；
- 旧 AI 计费表继续不存在；
- 没有自动新增角色权限关系。

## 19. 验证执行边界

本需求改动面较大，但不能因此默认运行耗时巨大的全仓测试。

Codex 实施时只自动执行与当前改动直接相关、预计单条两分钟内完成的命令，例如：

- 当前 Go package 的单元测试；
- 单个钱包/计费 repository 集成测试；
- 单个前端组件或 composable 测试；
- 价格目录 schema 校验；
- `git diff --check` 和文档/格式检查。

以下长脚本只写入 plan 和最终交付说明，由用户手动运行；除非用户当次明确授权，Codex 不执行：

- `go test ./...`；
- 全仓 `-race`；
- 前端全量 coverage、build、bundle/audit；
- Docker 构建或容器集成验证；
- 完整 runtime contract/reconciliation/release gate；
- 任何预计超过两分钟的批量验证脚本。

如果原本预计较短的命令实际超过两分钟，应停止继续等待，报告命令和当前状态，交给用户手动执行。不得为了宣称“全部通过”持续消耗数小时和大量 Token。

plan 必须把验证分成两栏：

1. `Codex targeted checks`：实施过程中自动运行的短测试。
2. `User-run full verification`：用户选择运行的完整脚本，不作为 Codex 结束当前实现工作的自动前置条件。

## 20. 针对性测试范围

短测试重点覆盖：

- 目录 schema、摘要、别名唯一性、生效价格和来源字段；
- 小于一分钱、最大值、倍率边界、溢出和最终向下取整；
- 缓存字段不存在与显式 0、OpenAI inclusive cached tokens、缓存写入/读取拆分、非法总量和工具轮次聚合；
- 未知模型或档位拒绝；
- 钱包冻结、补充、扣款、释放、退款、余额不足和并发幂等；
- 账单状态机与指纹冲突；
- 各模态在定价/余额失败时不调用供应商，成功时精确扣款；
- 过期冻结与不确定供应商结果恢复；
- cents 到 units 的精确迁移；
- 智能体倍率、价格预览、缓存明细、高精度金额和权限显示。

全量验证脚本仅作为用户手动的最终信心检查，不应重复拆成几十个由 Codex 长时间执行的步骤。

## 21. 验收标准

只有同时满足以下条件，本功能才算完成：

1. 官方 `$5 / M Token` 在目录中结算为 `¥5 / M Token`，不存在 FX 配置或隐藏换算。
2. 管理员只能修改智能体倍率，不能修改模型基础价。
3. 两个使用同一模型的智能体可以采用不同倍率。
4. 智能体切换模型后更换基础价但保留倍率。
5. 普通输入、缓存写入、缓存读取、输出和媒体用量形成独立不可变明细。
6. 缓存 Token 使用官方缓存价，并且不会重复进入普通输入。
7. 缓存明细缺失时不能按普通输入高价扣用户。
8. 小于一分钱的 AI 消费能够精确改变钱包，不设置一分钱最低消费。
9. 可用余额不足时不会调用供应商。
10. 重试后仍只产生一张账单、一次冻结扣款和一条钱包扣款流水。
11. 失败、取消、超时或无法恢复准确用量时，不捕获估算金额。
12. 图片、视频和音频按照模型真实官方单位计费，不回退到场景固定价。
13. 后续价格或倍率变化不能改变历史账单快照。
14. 旧 AI 计费表继续不存在，且没有自动角色授权。
15. Codex 只执行短而针对性的测试，长脚本明确交由用户手动运行。
