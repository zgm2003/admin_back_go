## 1. 这次减法要解决什么

项目的核心业务不是问题。真正拖慢开发的是围绕核心业务累积的重复治理表面：同一事实被复制到路由定义、权限种子、合同、golden、架构测试、计划、规格和运行文档中，普通 CRUD 也被迫承担高风险变更的流程成本。

本方向书的目标是：

1. 让简单 CRUD 有一条短、清楚、可复制的开发路径。
2. 让 MySQL 在本地开发中可以直接由初始化基线重建。
3. 从今天开始，数据库变化只通过少量、明确的 forward migration 加法进入。
4. 保留真正保护业务的约束、事务、授权、幂等和恢复机制。
5. 把过程材料、重复生成物和历史治理仪式移出主动开发上下文。

## 2. 不做什么

这不是微服务重写，也不是全仓机械合并，更不是删除安全边界。

以下内容在本轮减法中禁止删除或弱化：

- MySQL 唯一约束、外键、金额精度和事务边界；
- 服务端 RBAC、会话 rotation、密钥隔离和敏感字段加密；
- 支付验签、支付幂等、钱包账本和回调恢复；
- AI Conversation、Message、Run、Attachment 的持久化事实；
- Worker 任务的幂等、重试、终态收口和恢复；
- COS 对象授权；
- MySQL 与 Qdrant 的事实/派生索引边界；
- 直接验证以上不变量的行为测试。

## 3. 数据库决策：本地初始化基线

项目尚未上线，本地数据库允许清空重建。因此本地开发采用“初始化基线 + 从今天开始的增量迁移”。当前 Atlas 链不继续承载日常开发复杂度，但不会未经备份直接删除。

### 3.2 目标数据库目录

切换完成后，主动开发路径只保留：

```text
database/
  schema.sql          # 当前完整结构，初始化唯一结构事实
  seed.sql            # 最小必要系统数据
  migrations/         # 从本方向书日期之后新增的 forward migrations
  README.md           # 只说明初始化、增量和重建命令
```

旧 Atlas migration、legacy migration、reconciliation 和恢复材料先通过 Git tag 和外部备份保留，再从主动执行路径移出。未完成引用盘点前不得直接删除文件。

### 3.3 初始化内容和排除内容

`schema.sql` 只负责结构，不带业务开发数据，不写入密钥、证书、Provider secret、管理员密码或临时对象。

`seed.sql` 只保留启动系统所需的最小数据：

- 权限目录、必要角色和角色权限；
- 默认系统设置；
- 官方模型目录及其价格/用途事实；
- AI 工具目录；
- 上下文工程启动所需的必要默认配置。

以下数据不进入初始化 seed：用户、会话、聊天记录、AI Run、上传记录、支付订单、操作日志、队列历史、临时供应商配置、Qdrant 向量和本地测试数据。管理员账号通过本地初始化入口创建，密码不能硬编码在 SQL 中。

### 3.4 新迁移规则

从本方向书日期开始，新数据库变更只新增短的、按顺序执行的 forward migration，并由单一 `db` 入口调用。应用启动不自动迁移。

保留极小的迁移账本，只记录新基线之后已执行的迁移。由于本项目是本地开发，迁移失败的恢复方式优先是恢复备份或重建数据库，不再新增复杂的 reconciliation、rehearsal、跨阶段恢复仪式。

### 3.5 重建范围

重建不能只删除 MySQL。标准本地重建顺序是：

```text
停止 API/Worker
  -> 备份 MySQL
  -> 重建 MySQL schema.sql + seed.sql
  -> 清理 Redis 缓存、队列和会话状态
  -> 清理 Qdrant 派生集合
  -> 启动 API/Worker
  -> 验证 /ready 和关键页面
```

MySQL 是唯一业务事实源；Redis 和 Qdrant 不能保留与新数据库 ID 空间不一致的旧状态。

## 4. 代码决策：CRUD Lite

简单 CRUD 默认使用 3 至 4 个文件：

```text
internal/module/example/
  example.go                 # model、输入输出和简单业务规则
  repository.go              # GORM 查询和写入
  transport/admin/http.go    # request、handler、route、简单 presenter
  example_test.go            # 直接验证核心行为
```

不再强制每个 CRUD 建立独立的 `dto.go`、`request.go`、`response.go`、`handler.go`、`service.go`、`route.go`、`errors.go` 和 `presenter.go`。

只有出现以下真实复杂度时才升级为完整分层：事务边界、外部 Provider、支付/钱包、异步任务、复杂状态机、批量并发、一致性重试、细粒度权限审计、复杂查询或多平台 transport。

旧模块不进行全仓机械合并。以后真实修改某个简单模块时，才在行为不变和测试覆盖的前提下顺手收缩；认证、支付、AI、Realtime、任务和存储模块保留其现有边界。

## 5. 事实源收敛

目标不是“文件越少越好”，而是每一类事实可以指出唯一权威来源：

| 事实 | 目标权威来源 | 其他形式 |
|---|---|---|
| 数据库结构 | `database/schema.sql` | 新增 migration、测试数据库 |
| 数据库初始数据 | `database/seed.sql` | 由 seed 生成/校验的检查结果 |
| HTTP 路径和访问策略 | Go route metadata | OpenAPI/合同由它生成 |
| 权限目录 | 单一代码/数据目录 | seed、前端合同由它生成 |
| 业务错误 | 稳定 machine error code | 中文消息目录 |
| 当前架构 | 精简后的当前架构文档 | Git 历史中的旧设计 |
| 向量索引 | Qdrant 派生集合 | MySQL 文档/版本事实 |

当前前端仍锁定 `contracts/admin/v1`，因此合同不能在本阶段直接删除。必须先完成 artifact 化或等价的本地消费方案，再把生成合同移出日常源码 diff。

## 6. 测试和流程减法

测试按业务不变量保留，而不是按文件数量保留。

保留授权矩阵、事务回滚、唯一约束、幂等、并发 winner、任务恢复、支付金额、AI 消息终态和附件授权测试。删除或改写只检查固定文件路径、源码字符串、重复 golden 或生成物格式的测试。

工作流分级：

- L1：单模块 CRUD、字段映射和文案，只读目标模块、相似实现和直接测试；
- L2：跨模块接口、缓存、异步和共享 middleware，写一页变更说明并跑受影响测试；
- L3：认证、RBAC、支付、生产数据迁移、密钥、并发恢复和发布，才要求完整设计与门禁。

普通 CRUD 不再强制长 spec、长 plan、全仓上下文阅读或全套发布仪式。

## 7. 执行阶段

### 阶段 A：建立恢复点

- 为当前后端和前端提交建立可恢复 tag；
- 保留本次完整 MySQL dump 及其哈希；
- 记录当前合同版本、数据库版本和容器镜像版本；
- 冻结新增 plan/spec/golden 和新的数据库治理层。

### 阶段 B：制作并验证初始化基线

- 从当前最终 schema 提取结构 SQL；
- 排除 Atlas 账本、reconciliation 运行记录和开发数据；
- 整理最小 `seed.sql`；
- 在临时空库执行 `schema.sql + seed.sql`；
- 与当前运行代码做结构和关键数据校验；
- 只有验证通过后，才替换本地开发数据库。

### 阶段 C：切换本地运行入口

- 增加单一 `db init`、`db reset`、`db migrate`、`db check` 入口；
- 重建 MySQL、Redis 和 Qdrant 的本地状态；
- 验证 API readiness、管理员初始化和 AI 基础数据。

### 阶段 D：建立 CRUD Lite 样板

- 选择两个无外部副作用的简单模块；
- 用新 3 至 4 文件结构完成等价改造；
- 保留 API、数据库字段和前端合同兼容；
- 只运行目标包测试和必要契约检查。

### 阶段 E：外围归档和安全收口

- 归档已完成过程文档；
- 清理重复架构测试和未调用脚本；
- 修复管理读取 RBAC、Trusted Proxy、Admin 登录限流和过期文档；
- 最后再评估检入合同是否可以 artifact 化。

## 8. 完成标准

减法完成后：

- 新环境可以用 `schema.sql + seed.sql` 建立可运行数据库；
- 新增数据库变化只进入新的 forward migration；
- 本地故障可以重建，不需要理解几十份历史恢复脚本；
- 普通 CRUD 不需要长设计文档和十个生产文件；
- 核心支付、认证、AI、任务和授权不变量仍由代码、数据库约束和语义测试保护；
- 合同、权限、数据库和架构文档各自只有清楚可指认的权威来源；
- 所有删除都先有 tag、备份和引用盘点，不做不可恢复的直接删除。

## 9. 当前结论

今天可以把当前数据库导出作为初始化基线制作材料，但不能把原始 dump 直接命名为初始化 SQL。正确过程是：

```text
最新数据库
  -> 完整备份（可恢复）
  -> 结构提取 schema.sql
  -> 最小必要数据 seed.sql
  -> 临时空库验证
  -> 本地数据库重建
  -> 从今天开始只做增量加法
```

这把刀砍的是重复治理，不是业务正确性。
