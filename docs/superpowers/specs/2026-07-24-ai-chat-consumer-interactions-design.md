# AI 对话消费者交互补全设计

**日期：** 2026-07-24
**状态：** 待用户审核

## 1. 目的

当前 AI 对话页已经具备会话列表、消息发送、异步回复、取消生成、图片附件和 WebSocket 恢复能力，但消息级交互仍是 MVP。本文只补齐用户在截图中明确标记的功能，并同步精简两个关联页面：AI Runs 输入快照与充值收银台。

本文不是模型定价或钱包扣费设计。模型定价、消费倍率和钱包结算属于独立需求，不得混入本设计或后续实施计划。

## 2. 已确认需求

### 2.1 消息选择与删除

1. 用户可从一条消息进入当前会话的消息选择模式。
2. 进入选择模式时，默认同时选中该消息所属的用户问题和 AI 回复。
3. 用户可独立取消任意一条，因此允许：
   - 删除完整问答对；
   - 只删除用户消息；
   - 只删除 AI 回复；
   - 一次选择多个消息后批量删除。
4. 问答配对必须依据 `ai_reply_commands.user_message_id` 与 `assistant_message_id`，不得通过相邻位置猜测。
5. 删除是 `ai_messages.is_del` 软删除，不物理删除消息、AI Run、回复命令或未来的财务记录。
6. 删除后，后续模型上下文只使用仍然可见的消息。

### 2.2 编辑用户消息

1. 仅用户消息显示编辑入口。
2. 本期只允许修改文字。
3. 原消息中的图片附件与运行参数原样继承，不允许在编辑状态中新增、移除或替换附件。
4. 提交编辑后，从该用户消息开始切断当前可见消息尾部，并以新文字重新发起异步回复。
5. 被替换的旧消息继续保存在数据库中，但退出当前可见对话链。
6. 旧 AI Run 和相关审计记录永久保留。

### 2.3 重新生成

1. 仅已完成的 AI 回复显示重新生成入口。
2. 仅当该 AI 回复对应的用户消息仍在当前可见链中时允许重新生成；若用户已单独删除该问题，则隐藏重新生成入口，服务端也必须拒绝请求。
3. 重新生成复用对应用户消息的文字、附件和运行参数。
4. 重新生成创建新的回复命令与新的 AI Run。
5. 当前可见链只保留新问答版本；旧问答退出可见链，但旧消息、Run 和审计记录保留。
6. 本期不提供旧答案版本切换界面。

### 2.4 点赞

1. 仅 AI 回复可点赞。
2. 第一次点击设置点赞，再次点击取消点赞。
3. 点赞是服务端持久化状态，不使用仅限当前浏览器的本地状态。
4. 点赞记录归属对应 `ai_runs`，AI Runs 详情展示点赞状态与点赞时间。
5. 删除聊天消息不清除 Run 上的点赞记录。

### 2.5 免费朗读

1. 仅 AI 回复显示朗读入口。
2. 使用浏览器 `window.speechSynthesis` 与 `SpeechSynthesisUtterance`。
3. 优先选择 Google 中文音色，其次选择其他 `zh-CN` 系统音色，最后使用浏览器默认音色。
4. 同一时刻只朗读一条消息；支持开始、暂停/继续和停止。
5. 切换会话、离开页面或开始朗读另一条消息时，停止上一条朗读。
6. 不调用后端 TTS，不创建 AI Run，不产生模型费用。
7. 浏览器不支持该能力时禁用入口并给出简短提示，不回退到付费服务。

### 2.6 异步回复未读数

未读场景定义如下：

1. 用户在会话 A 发起异步回复。
2. 回复尚未完成时，用户切换到会话 B。
3. 会话 A 成功生成一条完整 AI 回复。
4. 会话 A 的未读数增加 `1`。
5. 用户进入会话 A 并看到消息后，未读数清零。

计数口径：

- 只统计成功落库且尚未读的 AI 回复；
- WebSocket 流式分片不计数；
- 失败、取消、超时和 `outcome_unknown` 不计数；
- 当前正在查看的会话完成回复后立即标记已读，不显示红点；
- 删除一条未读 AI 消息后，该消息不再计入未读数。

### 2.7 AI Runs 输入快照

运行详情中的“输入快照”不得继续直接展示嵌套转义 JSON。界面需要识别并结构化呈现：

- 用户文字；
- 附件名称；
- 附件类型；
- 附件大小；
- 附件 URL；
- 图片缩略图与预览入口；
- 运行参数（存在时）。

历史纯文本快照继续显示为普通文本；无法解析的历史内容安全回退为原文，不阻断运行详情。

### 2.8 充值页精简

1. 删除收银台页面的整个“最近充值”区域。
2. 删除其专用组件、样式和仅为该区域发起的数据读取。
3. “充值记录”Tab、记录列表、继续支付能力和相关 API 保持不变。

## 3. 明确不做

- 模型官方价格、消费倍率、钱包扣费与退款；
- 模型生成的推荐追问及固定推荐模板；
- 点踩、分享、收藏等未标记的新能力；
- 付费后端 TTS 或 Google Translate 非正式 TTS；
- 聊天中的历史答案版本切换；
- 物理删除消息、Run、回复命令或财务数据；
- 新建第二套 WebSocket 或新增“未读通知”事件；
- 删除充值记录 Tab 或充值记录 API；
- 改写历史 `ai_runs.input_snapshot` 数据。

现有复制消息能力继续保留，但不在本需求中扩展。

## 4. 现有架构约束

本设计沿用当前模块化单体边界：

```text
route -> handler -> service -> repository -> model
```

现有关键事实：

- `ai_messages` 已有 `is_del`，可承载消息软删除；
- `ai_reply_commands` 对 `user_message_id` 保持一对一唯一约束；
- `ai_runs` 已关联 `conversation_id`、`user_message_id` 与 `assistant_message_id`；
- AI 回复完成事件 `ai.response.completed.v1` 已是持久化 WebSocket 事件；
- 前端实时客户端已有事件去重、序列游标、断线重放和权威恢复钩子；
- 当前消息上下文只查询 `is_del=2` 的可见消息；
- 当前运行快照可能是纯文本、附件 JSON，或包含字符串化 `meta_json` 的外层 JSON。

因此，本需求不新增通用事件总线、不引入独立聊天服务，也不创建消息版本树。

## 5. 选定架构

### 5.1 保持线性可见对话链

编辑和重新生成都采用“替换当前可见尾部”的线性模型，不引入用户可切换的分支树：

```text
旧可见前缀 + 被替换问答 + 后续消息
               |
               +-- 软删除并保留审计

旧可见前缀 + 新用户消息 + 新回复命令 + 新 AI 回复
```

为了保留 `ai_reply_commands.user_message_id` 的一对一不变量：

- 编辑创建一条新的用户消息，文字使用编辑结果，元数据复制自原用户消息；
- 重新生成也创建一条新的用户消息，其文字和元数据完整复制自原配对用户消息；
- 两者都为新用户消息创建新的回复命令；
- 原用户消息及其后的旧可见消息统一软删除。

重新生成时虽然用户消息 ID 会变化，但内容与附件不变，用户界面仍表现为原问题获得了新答案。旧 ID 继续被原 Run 和回复命令引用，不破坏审计。

### 5.2 WebSocket 只负责到达通知

WebSocket 不作为未读数真相源：

```text
回复完成事务
  -> 写入 assistant message
  -> 绑定 ai_run.assistant_message_id
  -> 追加 durable ai.response.completed.v1

前端收到事件
  -> 当前会话：恢复消息后推进已读游标
  -> 非当前会话：刷新会话列表，展示服务端 unread_count

断线或事件过期
  -> 现有 realtime recovery
  -> 重新读取会话列表与消息
```

这样不会因重复事件、页面刷新、切换智能体或断线重连造成未读数漂移。

### 5.3 点赞归 Run，朗读留在浏览器

- 点赞评价的是一次具体模型输出，因此归属于 `ai_runs`，不塞入 `ai_messages.meta_json`。
- 朗读只是当前设备的无成本辅助交互，因此只存在于前端运行态，不写消息、Run 或钱包流水。

## 6. 数据模型

### 6.1 `ai_conversations`

新增：

| 字段 | 约束 | 含义 |
| --- | --- | --- |
| `last_read_message_id` | `BIGINT UNSIGNED NOT NULL DEFAULT 0` | 当前会话所有者最后确认已读的 AI 消息 ID |

不为该字段增加外键，避免与 `ai_messages.conversation_id` 形成循环删除关系。Service 必须验证游标消息属于当前用户的当前会话，并使用 `GREATEST(existing, incoming)` 单调推进，禁止回退。

### 6.2 `ai_messages`

不新增状态字段，继续使用：

- `is_del=2`：当前可见链；
- `is_del=1`：已从用户会话隐藏，但仍供 Run、回复命令和审计引用。

新增组合索引：

```text
(conversation_id, is_del, role, id)
```

该索引同时服务可见 AI 消息计数和已读游标之后的未读范围查询。

### 6.3 `ai_runs`

新增：

| 字段 | 约束 | 含义 |
| --- | --- | --- |
| `liked_at` | `DATETIME(6) NULL` | 非空表示当前用户已点赞，值为最近一次点赞时间 |

取消点赞将 `liked_at` 置空。本期不记录每次切换历史，也不预留点踩枚举。

### 6.4 不新增表

本需求不创建消息版本表、点赞表或会话未读明细表。会话当前只有一个所有者，现有表上的软删除、读游标和 Run 点赞时间已足够表达需求。

## 7. 服务端契约

具体 OpenAPI 名称可遵循仓库生成规则，但资源语义必须保持如下。

### 7.1 消息列表扩展

每条消息增加：

| 字段 | 含义 |
| --- | --- |
| `paired_message_id` | 当前可见问答对中的另一条消息 ID；无配对时为 `null` |
| `run_id` | AI 回复对应的 Run ID；用户消息为 `null` |
| `liked` | AI 回复是否已点赞；用户消息固定为 `false` |

配对和 Run 信息必须通过批量 JOIN/映射生成，禁止每条消息单独查询。

### 7.2 编辑消息

```text
POST /api/admin/v1/ai-conversations/:conversation_id/messages/:message_id/revisions
```

请求只接受：

```json
{
  "content": "修改后的文字",
  "request_id": "客户端幂等请求 ID"
}
```

服务端在一个事务内：

1. 锁定会话并验证所有权；
2. 按 `(conversation_id, request_id)` 先处理幂等重放；
3. 拒绝存在活动回复命令的会话；
4. 验证源消息为当前可见用户消息；
5. 记录事务开始时的当前可见尾部上界；
6. 将源消息到该上界之间的消息软删除；
7. 创建新用户消息，复制原 `meta_json`，只替换文字；
8. 创建新回复命令并更新 `last_message_at`；
9. 事务提交后唤醒现有回复执行器。

返回 HTTP 202 和新用户消息、回复命令、请求 ID。重复请求返回第一次创建的身份，不重复切断消息尾部。

### 7.3 重新生成

```text
POST /api/admin/v1/ai-conversations/:conversation_id/messages/:message_id/regenerations
```

请求只包含 `request_id`。服务端通过目标 AI 消息的回复命令找到配对用户消息，复制其文字和完整 `meta_json`，然后执行与编辑相同的“替换尾部并创建新回复”事务。

目标 AI 消息及其配对用户消息都必须仍然可见；任一消息已软删除时返回 404，不能借重新生成恢复用户已经删除的问题。

### 7.4 批量删除消息

```text
DELETE /api/admin/v1/ai-conversations/:conversation_id/messages
```

请求体为去重后的正整数 `ids`。服务端只软删除明确提交的消息 ID，不自动扩大到问答对；默认配对选择属于前端交互规则。

事务必须：

- 锁定并验证会话所有权；
- 拒绝空 ID、重复 ID、跨会话 ID 和不存在的可见消息；
- 拒绝存在活动回复命令的会话；
- 一次更新所有目标消息；
- 根据剩余可见消息重算 `last_message_at`。

### 7.5 推进已读游标

```text
PUT /api/admin/v1/ai-conversations/:conversation_id/read-cursor
```

请求包含 `message_id`。消息必须是该会话内已经成功落库的 AI 消息。更新只允许单调前进；重复请求幂等。

会话列表新增 `unread_count`，其含义为：

```text
conversation_id 相同
AND role = assistant
AND is_del = normal
AND id > last_read_message_id
```

### 7.6 Run 点赞

```text
PUT /api/admin/v1/ai-runs/:id/user-feedback
```

```json
{ "liked": true }
```

服务端验证 Run 属于当前用户、属于聊天会话、状态为成功且已绑定 AI 消息。`PUT` 是幂等设置，不实现计数累加。

AI Runs 详情增加 `liked` 与 `liked_at`；Run 列表本期不增加新列。

### 7.7 充值 PageInit

收银台不再消费 `recent`。若该字段只被此页面使用，则从 PageInit 查询与响应契约中移除，避免保留无消费者的数据库读取；充值记录列表接口不变。

## 8. 并发与状态规则

以下回复命令状态视为活动状态：

```text
pending / claimed / running / outcome_unknown
```

只要会话存在任一活动回复命令：

- 禁止编辑；
- 禁止重新生成；
- 禁止单条删除；
- 禁止批量删除。

用户必须先执行现有“停止生成”，并等待服务端进入 `canceled`、`failed`、`timed_out` 或 `succeeded` 终态。前端禁用按钮只是体验层；Service 与事务查询必须再次拒绝竞态请求。

编辑和重新生成一旦被服务端接受，就是一次已提交的会话历史改写。若后续供应商调用失败或被取消，新用户消息保留，旧尾部继续保持软删除，不跨外部调用回滚历史；用户可再次编辑该用户消息重新提交。

## 9. 前端交互

### 9.1 操作栏

- AI 回复：保留现有复制，新增朗读、点赞、重新生成。
- 用户消息：保留现有复制，新增编辑与删除入口。
- 桌面端在消息悬停或键盘聚焦时显示操作栏。
- 触摸设备必须通过可点击入口访问，不能依赖 hover。
- 每个图标使用现有图标库并提供 tooltip、`aria-label` 和稳定的按钮尺寸。

### 9.2 选择模式

- 进入后，当前会话头部显示“选择消息”和“取消”。
- 每条消息显示独立复选框。
- 初始选择为触发消息与 `paired_message_id` 指向的消息。
- 用户可任意调整选择结果。
- 底部固定显示删除按钮与已选择数量；空选择时禁用。
- 提交前使用现有确认组件确认，成功后退出选择模式并从本地会话缓存移除消息。

### 9.3 编辑与重新生成

- 编辑在原用户消息位置进入紧凑文本编辑态，不打开后台式大弹窗。
- 编辑器只加载文字，附件保持只读展示。
- 提交后立即退出编辑态，显示新的用户消息与异步回复占位。
- 重新生成开始后，按新的请求 ID 复用现有流式会话状态。
- 页面切换不丢失未完成回复，继续沿用按 `conversation_id + request_id` 管理的会话缓存。

### 9.4 未读徽标

- 会话列表项右侧显示红色数量徽标；`0` 不渲染。
- 徽标预留固定宽度，标题不得因数字出现而跳动或溢出。
- WebSocket 完成事件到达非当前会话时刷新权威会话数据。
- 进入会话、完成消息恢复并确认当前会话后，再推进最新可见 AI 消息的读游标。
- `realtime.resync_required` 继续走现有 recovery，不从本地累计值恢复。

### 9.5 输入快照展示

前端解析器按以下顺序处理：

1. 尝试解析外层 `input_snapshot`；
2. 若存在字符串类型 `meta_json`，再进行一次严格 JSON 解析；
3. 将 `content`、`attachments` 和 `runtime_params` 映射为结构化视图；
4. 解析失败时显示原始文本。

不得使用 `v-html` 展示快照。附件 URL 只允许现有受信任的 HTTP/HTTPS 展示与预览路径；文件名和参数值由 Vue 普通文本转义。

## 10. 错误处理

- 活动生成冲突返回 HTTP 409，并提示“请先停止生成”；
- 源消息已删除、角色错误或不属于当前会话返回 404，不泄露其他用户消息存在性；
- 空编辑文字返回 400；
- 重复 `request_id` 返回首次创建结果；
- 浏览器朗读不可用只影响朗读按钮，不影响对话；
- 点赞失败恢复按钮原状态并提示，不覆盖消息内容；
- 输入快照解析失败只回退显示原文，不使详情弹窗报错；
- WebSocket 丢失或重放异常时，以会话列表和消息 API 的恢复结果为准。

## 11. 安全与审计

- 所有消息变更、读游标和点赞接口都使用当前登录身份，服务端验证会话或 Run 所有权；
- 不接受前端传入 `user_id`、配对消息 ID、Run 归属或附件替换；
- 编辑、重新生成和删除的操作日志只记录资源 ID、请求 ID 和动作，不记录完整提示词、附件 URL 或模型回复正文；
- 软删除不得级联修改 `ai_runs`、回复命令、运行事件或未来财务记录；
- 浏览器朗读文本不发送到新服务，不使用非正式 Google TTS 网络接口。

## 12. 被否决的方案

### 12.1 前端本地未读计数

刷新即丢失，断线重放可能重复累加，多标签页也会漂移，因此不用。

### 12.2 每条完成事件直接持久化 `unread_count += 1`

删除未读消息和重复恢复需要额外对账，容易产生派生值漂移，因此使用读游标加查询计数。

### 12.3 修改原消息内容

会让旧 AI Run 看起来像由新提示词产生，破坏审计，因此编辑创建新消息并软删除旧可见尾部。

### 12.4 取消 `user_message_id` 一对一约束

会扩大回复命令、配对和幂等语义。重新生成通过复制用户消息创建新命令即可满足需求，无需破坏现有不变量。

### 12.5 独立点赞表

当前一次 Run 只有当前用户的“点赞/未点赞”状态，`ai_runs.liked_at` 已足够；独立表属于过度设计。

### 12.6 后端 TTS

会产生模型费用并引入默认音频智能体配置，本需求明确采用免费浏览器朗读。

## 13. 验证策略与执行预算

本节定义应覆盖的风险，不授权实现智能体自动运行长测试。

实现阶段默认规则：

1. 不自动运行 Docker、全量后端测试、全量前端测试、覆盖率、Playwright 全套或完整 smoke；
2. 不自动启动超过两分钟的验证命令；
3. 需要长链路验证时，只给出命令和预期结果，由用户决定是否手动执行；
4. 只有用户在当前对话明确授权后，才运行对应长测试；
5. 智能体默认只做 `git diff --check`、类型/编译级快速检查和用户明确允许的定向测试。

建议的定向覆盖点：

- 后端：编辑/重新生成幂等、活动命令冲突、任意消息软删除、已读游标单调性、Run 点赞所有权；
- 前端：默认问答对选择与独立取消、编辑仅文字、朗读状态清理、WebSocket 非当前会话未读刷新、快照三种格式解析；
- 手工：在会话 A 发消息后切换 B，等待完成，确认 A 显示 `1`，进入 A 后清零；
- 手工：删除问答对、只删用户、只删 AI 三种路径；
- 手工：运行中确认编辑/重生成/删除均不可用，停止并进入终态后恢复；
- 手工：AI Runs 详情能看到点赞与结构化附件快照；
- 手工：充值收银台不再出现最近充值，充值记录 Tab 保持正常。

## 14. 验收标准

1. 只实现本文第 2 节列出的标记功能。
2. 推荐追问没有接口、模型调用或 UI 占位。
3. 编辑只修改文字，附件和运行参数不变。
4. 编辑与重新生成产生新消息、回复命令和 Run，旧审计记录不变。
5. 用户可按问答对默认选择，也可只删除其中一条。
6. 活动生成期间，所有会改变历史的操作在前后端同时被阻止。
7. 点赞可切换，并在对应 Run 详情中持久展示。
8. 朗读完全在浏览器执行，不调用后端且不计费。
9. 异步回复在非当前会话完成后产生准确未读数，进入会话后清零，断线恢复不重复。
10. 输入快照以结构化内容展示，历史异常数据安全回退。
11. 收银台移除最近充值，充值记录能力不受影响。
12. 实施过程遵守第 13 节验证预算，不擅自运行长测试。
